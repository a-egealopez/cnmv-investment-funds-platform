# Architecture

Last updated: 2026-11-15

## Overview

Platform that turns the CNMV's public filings on Spanish investment funds (IIC) into a fund panorama, a watchlist of up to 20 compartments, and a layer of flows, fees and data-quality signals. It produces analytical signals, not investment recommendations.

## Stack

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Ingestion | Python (requests, lxml) | Incremental download of CNMV archives and ECB €STR series |
| Parsing | PySpark (local mode) | XML parsing with explicit schemas, nested structure flattening |
| Storage | Parquet (Silver), DuckDB (Gold) | Columnar files; in-process analytical database |
| Transformation | dbt Core + dbt-duckdb | SQL models, tests, documentation, lineage |
| Orchestration | Apache Airflow + DockerOperator | Weekly schedule, dependencies, retries |
| Packaging | Docker Compose | One image per stage (ingestion, spark, dbt) |
| CI/CD | GitHub Actions, GHCR, GitHub Pages | Lint, security scans, tests, dbt build, image publishing, dbt docs |
| BI | Power BI | Dashboard on the Parquet export |
| Exploration | Jupyter | Source profiling and threshold calibration |

## Data Layers

### Bronze (raw)
- Original ZIP archives from CNMV and ECB €STR CSVs. FONDMENS and FONDREGISTRO are monthly; FONDTRIM, FONDCART and FONDPATRIMDISVAR were quarterly until 2022 and are semiannual (06/12) from 2023
- Location: `data/raw/` (zips) and `data/bronze/` (extracted, per period)
- Immutable: never modified; source URL, download time, SHA-256 and size are recorded in `data/raw/manifest.csv` (ECB files in `data/raw/ecb/`)

### Silver (clean)
- Typed Parquet tables generated by PySpark, partitioned by `FechaDatos`:
  - `fund_nav_daily`: daily NAV, participants, patrimony (FONDMENS)
  - `fund_metadata`: fund name, manager, depositary, ISIN (FONDREGISTRO)
  - `fund_quarterly`: per class: AUM, participants, fees, official returns/volatility/TER for the current and three previous quarters; per compartment: investor vocation (FONDTRIM)
  - `fund_holdings`: portfolio position lines per compartment (FONDCART)
  - `fund_period_financials`: compartment-level expenses, income, net flow, net return, turnover and patrimony, cumulative year-to-date (FONDPATRIMDISVAR)
  - `estr_daily`: ECB compounded €STR index and rate series (long table, keyed by `series`)
- Location: `data/silver/`
- Coverage: 80 monthly periods (202001–202608) for FONDMENS/FONDREGISTRO and 13 semiannual closings (202006–202606) for FONDTRIM/FONDCART/FONDPATRIMDISVAR. The 03/09 files published until 2022 stay in Bronze only (see `docs/analytics/sources.md`)

### Gold (analytical)
- Business-ready models generated by dbt (dbt-duckdb) in `data/gold/cnmv.duckdb`, organised as a constellation of star schemas (one fact per business process, shared conformed dimensions):
  - **Dimensions**: `dim_compartment`, `dim_class`, `dim_date`, `dim_manager_group`
  - **Facts**: `fact_nav_daily`, `fact_class_nav_weekly`, `fact_fund_quarterly_metrics`, `fact_compartment_monthly`, `fact_holdings`, `fact_fund_period_financials`, `fact_manager_group_monthly`, `fact_market_fee_and_aum`, `fact_estr_weekly`, `fact_fund_anomalies`
  - **Marts**: `mart_fund_panorama` (one row per active compartment through its representative class: 3- and 5-year metrics, AUM, participants, concentration, latest flows and fees, flags, watchlist status) and `mart_fund_class_status` (why each class is or is not in the panorama)
- `dbt build` is green on real data and on the CI fixture
- Grains and column descriptions live in `dbt/models/**/*.yml` (in Spanish). CI generates the static docs with the lineage graph from the same commit, and CD publishes them to GitHub Pages. Locally: `cd dbt && dbt docs generate --static`
- BI export: `python -m bi.export_gold` writes `data/exports/gold_bi/*.parquet` plus `_manifest.json`

## Pipeline

```
Airflow DAG cnmv_pipeline (weekly), one DockerOperator task per stage:
1. ingestion  download every CNMV period published since 202001 that is not yet in the manifest, plus €STR
2. spark      parse new or changed Bronze periods into Silver (build_silver.py --pending)
3. validate   quality gate on Silver (validate_silver.py, FINDINGS contract)
4. freshness  dbt source freshness: warns when a source is older than its publication cadence allows
5. dbt        dbt build: staging (views) → intermediate → dimensions, facts and marts (tables), with meta_run as the single cut-off
6. export     Gold tables to Parquet for Power BI
```

Without Airflow, `docker compose up` runs the same six stages in order and stops at the first failure; `docker compose run --rm --no-deps <service>` runs one stage.

## Design Decisions

- **PySpark in local mode**: handles complex nested XML with explicit schemas; at this volume a single machine is enough, so no cluster is used
- **DuckDB**: full analytical SQL (window functions, ASOF joins) without a server
- **Airflow only orchestrates**: every stage runs in its own container, so Airflow carries none of the project's dependencies and a stage's exit code decides success or failure
- **Full rebuild by `as_of_period`**: `meta_run` resolves the cut-off once (`latest` or an explicit `YYYYMM`) and every model reads it from there. The cut applies to all facts and dimensions, so a rebuild with an earlier cut contains no later data (checked with 202512; with data from 2020-01 the first cut with a complete 3-year window is 202212 and with a complete 5-year window 202412). Staging models are views; the rest are tables rebuilt on each run. At the current volume this is fast and keeps `dbt build` idempotent; incremental materializations can be introduced when volume or runtime justifies them
- **Provenance**: Bronze records source URL, download time, period and file hash in `data/raw/manifest.csv`; each dbt run records `as_of_period` in `meta_run`. A Gold row can be traced back to its Silver partition and, through the period, to the source archive
- **Semiannual cadence in Silver**: only the 06/12 closings of the periodic sources are loaded, giving one homogeneous series from 2020; quarterly official metrics are not lost because each FONDTRIM file reports four quarters
- **Exploration notebooks**: grouped by decision question, not one per source. `01` profiles NAV/metadata anomalies, `02` calibrates selection thresholds from the semiannual snapshots, and `03` validates the FONDPATRIMDISVAR financial contract

## Next: cloud deployment

The next release moves the same containers to AWS (S3 for the data layers, ECS Fargate for the stages, IAM roles and GitHub OIDC instead of long-lived credentials). It is planned, not built.
