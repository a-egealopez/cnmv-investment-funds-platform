# Architecture

Last updated: 2026-09-26

## Overview

Platform for analyzing Spanish IIC (Collective Investment Schemes) to generate short-term buy/sell signals on fund assets.

## Stack

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Parsing | PySpark | XML parsing, nested structure flattening |
| Storage | DuckDB | Analytical database, advanced SQL support |
| Transformation | dbt | SQL models, tests, documentation |
| Orchestration | Airflow | Pipeline scheduling, dependencies, retries |
| Exploration | Jupyter | Interactive analysis and validation |

## Data Layers

### Bronze (raw)
- Original ZIP files from CNMV
- Location: `data/raw/`
- Immutable: never modified

### Silver (clean)
- Normalized parquet tables generated by PySpark:
  - `fund_nav_daily` — daily NAV, participants, patrimony
  - `fund_metadata` — fund name, manager, depositary, ISIN
  - `fund_holdings` — portfolio holdings, sectors, weights
- Location: `data/silver/`

### Gold (analytical)
- Business-ready models generated by dbt:
  - `mart_fund_rankings` — risk-adjusted performance rankings
  - `mart_sector_allocation` — aggregate sector exposure
  - `mart_holdings_rotation` — inter-period changes
- Location: `data/gold/`

## Pipeline (monthly)

```
1. Download FONDMENS ZIP + new IPP per nreg
2. PySpark: parse XML → Silver parquet tables
3. dbt: SQL transformations → Gold analytical models
4. Analysis: SQL queries on Gold tables
```

## Design Decisions

- **PySpark standalone**: selected for pedagogical purposes and ability to handle complex nested XML schemas locally without a cluster
- **DuckDB**: supports advanced SQL (window functions, CTEs) without a server
- **Airflow**: added after local pipeline is working
- **Solo project**: lightweight tools, no production infrastructure
